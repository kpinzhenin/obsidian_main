Присутствует большая небольшая разница в загрузках под управлением [[BIOS]] и  [[UEFI]]. Разница начинается после проверки POST кодов.
### BIOS 
Загрузка операционной системы начинается с *загрузочного сектора* `boot sector`.
`boot sector` описывается как первые 512 байт на жестком диске, плюс 31KB. В каждом разделе резервируется место ( 512b + 31KB ) под `boot-related information( VBR Volume Boot Record или все таки Virtual Boot Record )` и это не MBR!. MBR как раз одна на весь HDD.
Master boot record( MBR ) = Boot record = Boot sector = Bootloader
Предполагается, что 1 сектор = 512 байт. современный размер сектора походу все таки 4 KB.
Загрузчик ( `bootloader` ) делится на 3 части:
 - bootstrap ( 440 bytes ), DeepSeek называет его *"First-stage bootloader"*
 - bootloader ( 31 KB ) это как я понял и есть `VBR( Volume Boot Record)` каждого раздела
 - Часть ядра операционной системы из состава кода основного раздела
 Оказывается 512 байт связаны с тем, что BIOS не умеет читать дальше первого сектора.
every partition has 512 bytes + 31 KB of space reserved for booting purposes, and this space is hidden from the user.
### UEFI
Вместо MBR здесь у нас [[ESP]]. И кажется все ОС должны записывать свои `bootloaderы` в один каталог EFI/ который видимо в одном и том же разделе. При этом раздел [[ESP]] в `Linux` монтируется в `/boot/efi`.
тем не менее - UEFI видит все загрузчики установленных ОС, которые можно выбрать при запуске ПК. При этом если загрузчик поддерживает - он в свою очередь тоже предоставляет выбрать загрузчик из установленных.

А при установке Windows, свой bootloader она записывает в `/boot/efi/EFI/Microsoft/bootmgfw.efi`. Вспоминая, что при установке Ubuntu выбирался раздел для установки [[ESP]] в раздел 1, получается что `/boot/efi/EFI/` указывает на раздел 1, а не на раздел с установленной ubuntu.

Примечательно, что при установке новой ОС под ESP закладывается аж 3Гб....
Примечательно, что UEFI умеет распознавать загрузчики, уже установленные в устройствах ( HDD, USB и т.д. по порядку загрузки )
